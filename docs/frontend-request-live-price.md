# 프론트 작업 요청 — 종목 현재주가 자동 갱신

작성: 2026-08-18 / 백엔드 세션 → 프론트 세션 인계
백엔드는 **구현 완료**. 아래는 프론트에서 바꿀 것만 적는다.

> 이 문서는 한 번 갈아엎었다. 처음에는 수집 시세를 `live` 라는 별도 객체로 실어 보냈는데,
> `current_price` 를 그냥 갱신하면 될 일이었다. 컬럼 이름이 이미 "현재주가" 다.
> **`live` 객체는 없다.** 혹시 그걸로 작업하셨다면 아래 내용으로 대체해 달라.

---

## 0. 무엇이 바뀌었나

**`securities.current_price` 가 수집된 실제 시세로 자동 갱신된다.**

지금까지 사람이 손으로 넣던 값이다. KIS 연동이 없어서 그랬을 뿐, 그 컬럼의 뜻은
원래부터 "현재주가" 였다. 이제 수집기가 직접 채운다.

```
장중        5분마다 현재가로 갱신
장 마감 후  16:10 일봉 수집 시 그날 종가로 갱신
```

즉 **프론트에서 `current_price` 를 읽는 코드는 그대로 두면 된다.** 값이 알아서 실제
시세가 된다. `market_value`(평가금액)도 이 값을 쓰므로 함께 정확해진다.

---

## 1. 추가된 필드 두 개

값 자체는 `current_price` 에 있고, 그 숫자를 읽는 데 필요한 맥락만 덧붙였다.

```json
{
  "symbol": "005930", "name": "삼성전자",
  "current_price": "271500.00",                    // 실제 시세 (자동 갱신됨)
  "market_value": 138193500.0,                     // 실제 시세 × 보유수량
  "price_at": "2026-08-18T04:00:00.053766+00:00",  // 그 가격이 관측된 시각 (UTC)
  "price_source": "SNAPSHOT"                       // 어디서 온 값인지
}
```

| `price_source` | 뜻 | 언제 |
|---|---|---|
| `SNAPSHOT` | 장중 현재가 | 장중 (5분마다 갱신) |
| `MINUTE` | 분봉 종가 | 장중 일부 구간, 마감 직후 |
| `DAILY` | 일봉 종가 | 장 마감 후·주말·휴장일 |
| `null` | 수집 안 되는 종목 | 사람이 입력한 값이 그대로 있다 |

백엔드는 장 시간을 판정하지 않는다. 세 후보의 관측 시각을 비교해 가장 최근 것을 고른다.
그래서 장중/장후 분기가 저절로 맞고, 공휴일 달력도 필요 없다.

---

## 2. 요청사항

### 2-1. 가격 옆에 시각·출처 표시

같은 숫자라도 장중이냐 마감 후냐에 따라 뜻이 다르다. 장중 271,500은 "지금 이 값"이고
마감 후 271,500은 "오늘 종가"다. 이걸 구분해 줘야 한다.

```
271,500  (3분 전)          ← SNAPSHOT / MINUTE  : 상대시간
271,500  (8/18 종가)        ← DAILY              : 날짜 + "종가"
271,500  (수기 입력)        ← null               : 수집 안 되는 종목
```

`DAILY`인데 "18시간 전"처럼 상대시간으로 쓰면 장 마감 후에 이상해 보인다.
`price_at`은 **UTC**로 오니 KST로 변환해서 표시한다.

```js
const isLive = sec.price_source === "SNAPSHOT" || sec.price_source === "MINUTE";
const isClose = sec.price_source === "DAILY";
const isManual = sec.price_source === null;
```

### 2-2. 종목 폼의 `현재주가` 입력 필드 처리

`forms/specs.js`에 `current_price` 입력 필드가 있다면 **읽기 전용으로 바꾸거나 빼 달라.**
지금은 사용자가 입력해도 다음 수집 주기(5분)에 덮인다. 입력칸이 남아 있으면
"입력했는데 값이 바뀌었다"는 혼란이 생긴다.

다만 **수집되지 않는 종목**(해외 종목 등, `price_source === null`)은 수기 입력이 유일한
방법이다. 이 경우엔 입력을 열어 두는 게 맞다. 판단이 어려우면 그냥 읽기 전용으로 두고,
필요해질 때 다시 열자.

### 2-3. `live` 객체를 쓰는 코드가 있으면 제거

이전 버전 문서를 보고 `sec.live?.price` 같은 코드를 넣으셨다면 지워야 한다.
그 필드는 응답에 없다. `sec.current_price`를 그대로 쓰면 된다.

## 3. 실제로 이렇게 바뀌었다

```
갱신 전 (사람이 입력한 값)      갱신 후 (실제 시세)
  삼성전자    277,500      →      271,500
  현대자동차  446,000      →      439,500
  SK하이닉스 1,727,000     →     1,672,000
```

포트폴리오 평가액이 수백만 원 단위로 달랐다. 이제 맞는 값이 나온다.

## 4. 성능

목록 API 조회 쿼리 **1회**다. 종목이 늘어도 늘지 않는다(서브쿼리로 붙인다).
추가 API 호출 없이 지금 부르는 종목 API 하나로 끝난다 — `market-symbol`을 따로 불러
종목코드로 매칭하는 코드가 있다면 지워도 된다.
