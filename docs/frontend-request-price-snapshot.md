# 프론트 작업 요청 — 가격데이터 자동 채움 (전략 근거 스냅샷)

작성: 2026-08-18 / 백엔드 세션 → 프론트 세션 인계
백엔드는 **구현 완료**. 아래는 프론트에서 바꿀 것만 적는다.

---

## 0. 무엇이 바뀌었나

`StrategyPage`의 **가격데이터** 탭에서 고가·저가를 손으로 입력하던 것이, 이제 **수집한 시세에서 자동으로 채워진다.**

```
종목만 고르고 저장   →  백엔드가 캔들에서 고가·저가를 읽어 채운다
                        당일  → 그 시각까지의 분봉 집계 (고가=최댓값, 저가=최솟값)
                        과거  → 그날 일봉의 고가·저가
```

**한 번 만들어진 행은 다시 바뀌지 않는다.** 수집이 아무리 돌아도 이 행은 건드리지 않는다.
전략의 근거 가격이 나중에 따라 움직이면 "왜 이 가격대에 걸었지"를 되짚을 수 없기 때문이다.

---

## 1. 저장 전 미리보기 — 새 엔드포인트

```
GET /api/trading/security-price-data/preview/?security_id=3
GET /api/trading/security-price-data/preview/?security_id=3&price_at=2026-08-14T05:00:00Z
```

```json
{
  "success": true,
  "results": {
    "security": 3, "security_name": "현대자동차", "symbol": "005380",
    "price_at": "2026-08-18T05:00:39.841606+00:00",
    "high_price": "459500.00",
    "low_price": "435500.00",
    "price_source": "MINUTE"
  }
}
```

**아무것도 저장하지 않는다.** 값만 계산해 보여 준다.

| `price_source` | 뜻 |
|---|---|
| `MINUTE` | 당일 분봉을 집계한 값 |
| `DAILY` | 그날 일봉의 확정 고가·저가 |
| `null` | **그 시점 시세가 수집되지 않았다** |

받는 파라미터는 `security_id`, `price_at` 둘뿐이다. 다른 걸 붙이면 400이다.
`price_at`을 생략하면 지금 시각 기준이다.

## 2. 요청사항

### 2-1. 가격데이터 폼을 "종목 + 기준일시"로

지금 폼은 고가·저가·호가를 직접 입력받는다. 이렇게 바꿔 달라.

```
종목        [현대자동차 ▾]         ← 필수
기준일시    [2026-08-18 14:00]     ← 비우면 지금 시각

─────────────────────────────────
 수집된 시세                        ← preview 결과를 즉시 표시
   고가  459,500
   저가  435,500
   출처  당일 분봉 집계
─────────────────────────────────

호가        [          ]           ← 선택 입력 (자동으로 안 채워짐)
```

- 종목이나 기준일시를 바꾸면 **preview를 다시 불러 값을 갱신**한다
- 저장할 때는 `{"security": 3, "price_at": "..."}` 만 보내면 된다. 고가·저가는 백엔드가 채운다
- 고가·저가를 **직접 넣고 싶으면 실어 보내면 된다.** 보낸 값이 그대로 저장되고 자동 채움은 건너뛴다

### 2-2. 시세가 없을 때 안내

`price_source`가 `null`이면 그 시점 시세가 없다. 저장을 시도하면 400이 뜬다:

```json
{"high_price": ["현대자동차(005380) 의 해당 시점 시세가 수집되지 않았다. 일봉을 먼저 수집하거나(kis_backfill_daily), 고가·저가를 직접 입력하라."]}
```

**미리보기 단계에서 미리 막아 달라.** `price_source === null`이면:

```
수집된 시세가 없습니다.
과거 일자는 일봉 수집이 필요합니다. 또는 고가·저가를 직접 입력하세요.
[직접 입력하기]
```

`[직접 입력하기]`를 누르면 고가·저가 입력칸이 열리는 식이면 흐름이 끊기지 않는다.

> **지금은 과거 일자가 대부분 `null`이다.** 일봉이 아직 0건이라(`kis_backfill_daily` 미실행) 당일 분봉만 있다. 사용자가 backfill을 돌리면 과거도 채워진다.

### 2-3. 호가는 자동으로 안 채워진다

`quote_price`는 비워 둔다. 호가는 체결가가 아니라 주문 대기 가격이라 봉 어디에도 없고,
KIS도 과거 호가는 주지 않는다(실시간 10호가만).

종가나 현재가로 대신 채우지 말 것 — 컬럼 이름이 "호가"인데 다른 값이 들어가면 나중에
읽는 사람이 호가인 줄 알고 틀린 판단을 한다. 필요하면 사람이 적어 넣는 칸으로 남긴다.

### 2-4. 수정 화면에서는 자동 채움이 없다

`PATCH`에는 자동 채움이 걸리지 않는다. 빈 칸을 나중에 채우려고 수정 요청을 보내면
**그 시점 시세**가 들어와 스냅샷이 오염되기 때문이다.

수정 화면에서는 값을 직접 고칠 수 있게만 하고, "시세로 다시 채우기" 같은 버튼은 두지 말 것.
값을 다시 뜨고 싶으면 새 스냅샷을 만드는 게 맞다.

---

## 3. 왜 이렇게 하나 (한 줄 요약)

가격데이터는 **시세 저장소가 아니라 "전략을 세운 순간 무엇을 보고 있었나"의 기록**이다.
시세를 보고 싶으면 `market-daily-candle` / `market-minute-candle` API를 쓰면 된다.
