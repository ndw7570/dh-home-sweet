# 백엔드 작업 요청 — 매수매도방법 템플릿 (이름 칸 + 전략에 적용)

작성: 2026-08-18 / 프론트 세션 → 백엔드 세션
**방향이 반대인 문서다.** 지금까지의 `frontend-request-*.md` 는 백엔드→프론트 인계였고,
이건 프론트가 막혀서 백엔드에 요청하는 것이다.

---

## 0. 만들려는 것

전략 화면에 **매수매도방법** 탭을 넣는다(매수매도전략 / **매수매도방법** / 가격데이터).

```
매수매도방법 목록
  분할매수 A                    분할매수 B
    1차   -3%   30%              1차   -5%   50%
    2차   -7%   30%              2차  -10%   50%
    3차  -12%   40%

전략에서 "분할매수 A" 를 고르면 → 그 세 줄이 전략의 분할표로 복사된다
```

**방법 한 개 = n차 표 한 벌**이다(줄 하나가 아니라). 전략마다 같은 분할표를 다시 입력하지
않으려고 미리 만들어 두는 서랍이다.

---

## 1. 지금 상태 (실측)

`trading_strategy_methods` 를 그대로 쓸 수 있다. 확인한 것:

- `TradingStrategyMethod.verbose_name` 이 이미 **"매수매도방법"** 이다.
- `strategy` 가 **nullable** 이고, `strategy: null` 로 POST 하면 **201 로 만들어진다.**
  (확인 후 해당 행은 purge 로 지웠다. 지금 이 표는 id 1·2 두 건 그대로다.)

즉 **전략에 안 붙은 행 = 템플릿** 으로 두면 새 모델이 필요 없다.

막힌 것은 두 가지다.

---

## 2. 요청 — `name` 칸

**여러 벌을 구분할 이름이 없다.** 지금 컬럼으로는 `분할매수 A` 와 `분할매수 B` 를 나눌 수 없다.

```
trading_strategy_methods
  + name VARCHAR(100) NULL    -- 방법 이름. 같은 이름끼리 한 벌이다.
```

- **nullable 로 둘 것.** 기존 2건은 전략에 붙어 있는 실제 분할표라 이름이 없다.
- 한 벌의 정의: `strategy IS NULL` 이면서 `name` 이 같은 행들. 표시 순서는 `step_no`.
- `remarks` 나 `sector` 를 이름 자리로 쓰는 것은 안 하기로 했다 — 비고는 비고대로 쓸 자리가
  필요하고, 업종은 같은 업종에 방법이 둘일 때 못 나눈다.

---

## 3. 요청 — 템플릿만 조회

지금 필터 화이트리스트는 `strategy_id` · `strategy_type` · `sector` 뿐이라
**"전략에 안 붙은 행만" 을 물을 방법이 없다.** 전량을 받아 화면에서 거르면, 전략이 늘수록
쓰지도 않을 분할표를 계속 내려받게 된다.

```
GET /api/trading/trading-strategy-method/?template=1   → strategy IS NULL 인 행만
GET /api/trading/trading-strategy-method/?template=0   → 전략에 붙은 행만
```

이름이 `template` 이 아니어도 된다. **`strategy IS NULL` 을 물을 수 있으면 무엇이든 좋다.**

---

## 4. 요청 — 전략에 적용 (한 번에)

```
POST /api/trading/trading-strategy/{id}/apply-method/
{ "name": "분할매수 A" }
```

그 이름의 템플릿 줄들을 이 전략의 분할표로 **한 트랜잭션에** 복사한다.

프론트에서 줄 수만큼 POST 를 돌릴 수도 있지만 그러면 **3줄 중 2줄만 들어간 전략**이 생긴다.
분할표는 수량 비중의 합이 100% 여야 뜻이 있는 표라, 반쯤 채워진 상태는 틀린 값보다 나쁘다.
화면이 그걸 되돌릴 방법도 없다.

정해 줘야 할 것:

- 이미 분할표가 있는 전략에 적용하면 **덮어쓰기인가 덧붙이기인가.** 프론트는 덮어쓰기를
  기대한다(같은 n차가 두 벌 생기면 표가 깨진다). 덮어쓰기라면 응답에 지워진 줄 수를 주면
  화면이 "3줄을 4줄로 바꿨다" 고 알릴 수 있다.
- 없는 이름이면 400.

---

## 5. 안 해도 되는 것

- **새 모델·새 테이블.** 위 세 가지면 기존 표로 충분하다.
- **템플릿 CRUD 엔드포인트.** 지금 `trading-strategy-method` 의 CRUD 를 그대로 쓴다
  (`strategy: null` 로 만들면 템플릿이다).

## 6. 프론트 진행 상태

**대기 중이다.** `name` 이 없으면 목록을 벌 단위로 묶을 수 없어서 화면을 못 그린다.
2번(`name`)만 들어와도 탭·목록·수정까지는 바로 만들 수 있고, 3·4번은 그다음에 붙인다.
